# Автоматические ссылки на публикации в блоге

Генератор `scripts/update-blog.js` получает шесть последних постов Telegram.
Перед созданием карточек `scripts/blog-dzen-sync.js` читает публичный канал
`https://dzen.ru/voronova_nutrition` через браузер и ищет соответствующие статьи.
Вход в аккаунт Дзена не требуется.

Сборщик читает полные тексты последних статей (до 24). Совпадение требует
минимум 40 общих содержательных слов, пересечения словаря минимум 45 процентов
и общего фрагмента из 8 последовательных слов, включая 6 разных. Сравниваются
первые 450 слов; заголовки и часть формулировок могут отличаться. Лучшее совпадение
должно опережать следующее минимум на 15 процентных пунктов.
При нескольких подходящих статьях или постах ссылка не добавляется.
Порядок публикаций и номера сообщений не используются для угадывания ссылок.
Сильно переписанная статья может остаться без автоматического совпадения.

Найденные ссылки записываются в `data/blog-dzen-links.json`. Старые, в том числе
вручную заданные, ссылки сохраняются. При недоступности Дзена обновление постов
Telegram продолжается; сохранённые ссылки не удаляются. Следующий запуск снова
проверяет посты без ссылки.

GitHub Actions устанавливает Chromium, выполняет проверки, запускает генератор
и сохраняет найденные ссылки вместе с карточками. Расписание: каждые 6 часов.
Фактический запуск может происходить позднее времени расписания.

Для локальной проверки:

```powershell
npm install
node --test scripts/__tests__/blog-dzen-sync.test.js
# Установленный локальный Chrome:
$env:BLOG_BROWSER_CHANNEL = 'chrome'
node scripts/update-blog.js
```

Этот запуск изменяет блог, изображения, sitemap и таблицу ссылок Дзена.

## ВК: сборщик полного канала

Текущие ссылки ведут на сообщения канала ВК `-232523704`, а не на стену сообщества.
Проверка 2026-10-04 в отдельном браузере без авторизации открыла страницу входа ВК.
`scripts/blog-vk-reader.js` читает полный канал с сохранённым входом. Он
проверяет адрес канала и работает только внутри `.ChannelMain`. Текст берётся
из `.PostText`, идентификатор сообщения — из `data-itemkey` у
`.PostsList__item`. Ссылки внутри текста на предыдущие сообщения не используются
как адрес текущего поста. Сборщик читает до 24 сообщений; если виртуальная лента
не позволяет прокрутку, используются доступные сообщения. Результат сопоставления
сохраняется в `data/blog-vk-links.json`, ручные ссылки сохраняются.

Пользователь публикует полный текст в канале и анонс на стене сообщества
`https://vk.ru/voronova_nutrition` (проверенный ID сообщества: `229107522`).
Стена доступна в отдельном браузере без авторизации. В проверенном анонсе о кофе
`https://vk.ru/wall-229107522_350` нет ссылки на конкретное сообщение канала:
текст упоминает полную версию, но адрес сообщения не указан.

Открытая стена может служить источником адресов полных постов, если анонс
содержит конкретную ссылку на сообщение канала. При отсутствии такой ссылки
заменять кнопку полного поста ссылкой на анонс без согласования нельзя.
Для сохранения нынешнего назначения кнопки используется авторизованное чтение
полного канала. Пароли и cookies не следует
передавать в чат или включать в Git.

Для входа подготовлен `scripts/setup-blog-vk-login.js`. Он открывает отдельное
окно Chrome на странице канала. Пользователь входит напрямую в ВК; скрипт
не вводит и не записывает пароль. После подтверждения `READY` сохраняются
только cookies ВК в `.blog-sync-private/vk-state.json`, исключённый из Git.
localStorage, IndexedDB и кэш переписки не сохраняются. Режим `--auto` сам
сохраняет вход после появления сообщений нужного канала и закрывает окно.
Для локального однократного чтения используется `BLOG_VK_STATE_FILE`.
Содержимое сессии не включается в Git и журналы.

`scripts/blog-vk-links.js` проверяет точные адреса сообщений нужного канала
и использует общий механизм сопоставления полных текстов. Он не подменяет
сообщение ссылкой на анонс стены. При проверке ВК «не робот», истёкшем входе
или изменении структуры канала старые кнопки сохраняются; Telegram и Дзен
продолжают обновляться. Actions отмечает ошибку чтения ВК как неудачный запуск.
Повторный вход при необходимости выполняется пользователем напрямую в ВК;
серверный сборщик сохраняет свою сессию только в закрытый файл на сервере.
Проверка «не робот» не обходится.

После подтверждения входа пользователем сборщик ВК прочитал 10 сообщений и сам
сопоставил четыре текущих поста Telegram. Контрольный запуск GitHub Actions
`37197900436` получил `VK_CHALLENGE_REQUIRED`: с серверов GitHub канал требует
ручной проверки. Такой запуск не подтверждает автоматизацию ВК.

## Постоянный сборщик на сервере

Пользователь выбрал сервер сайта для круглосуточного чтения. Новый сборщик
`scripts/blog-vk-collector.js` использует один живой браузер между проходами,
проверяет ленту каждые пять минут и обновляет страницу не чаще одного раза
в шесть часов. При проверке ВК он ожидает ручного входа в том же браузере;
проверка не решается и не обходится автоматически.

Чтение и публикация разделены: постоянный браузер сохраняет ссылки в закрытый
файл `private/vk-links-preview.json`, отдельный издатель `--publish-snapshot`
объединяет свежие результаты с таблицей в основной ветке. Издатель принимает
только подтверждённые результаты не старше 30 минут, сохраняет актуальные ручные
ссылки и проверяет принадлежность новых адресов полному каналу. Остановка или
ошибка чтения не считается успешной публикацией.

Изолированная папка: `/home/smartplate-admin/blog-vk-sync/`. Cookies и состояние
сборщика находятся в `private/` с доступом только владельца; зависимости браузера
распакованы в `runtime-libs/`, системные пакеты не менялись. Рабочий репозиторий
отдельный от SmartPlate API. Сборщик проверяет точный remote репозитория сайта,
отказывается от публикации при любых посторонних изменениях и добавляет в Git
только `data/blog-vk-links.json`. Force push не используется.

GitHub Actions использует `BLOG_VK_SYNC_MODE=external`: читает уже найденные
ссылки, без входа в ВК с серверов GitHub. Изменение таблицы ВК в main запускает
обновление карточек; обычное расписание каждые шесть часов сохраняется.

Сеть сервера сайта не получает `t.me` (проверено: HTTPS заканчивается
`ETIMEDOUT`, включая IPv4). Поэтому генератор GitHub также автоматически
сохраняет `data/blog-telegram-posts.json`: только номера и полные тексты шести
публичных постов автора, без cookies, картинок и данных аккаунта. Постоянный
сборщик с `BLOG_TELEGRAM_SOURCE=github` получает этот файл по HTTPS из main
на GitHub. Источник и формат проверяются; ошибка чтения не удаляет кнопки.
Это сохраняет обычную периодичность обновления Telegram каждые шесть часов.

`scripts/setup-blog-vk-server.js` открывает локальное окно ручного входа в
серверный браузер через SSH-туннель. Управление и кадры доступны только на
127.0.0.1, действия защищены случайным токеном. Пароли и кадры не записываются
в файлы или журналы. Браузер сборщика остаётся на сервере после закрытия окна.
Помощник не закрывается по таймеру: пользователь закрывает окно самостоятельно.
Окно авторизации ВК, открытое в отдельной вкладке серверного браузера,
автоматически становится доступно для управления. Действия передаются по очереди.
Для номера или кода можно нажать нужное поле на изображении ВК, ввести текст
в поле сверху и нажать «Ввести в выбранное поле ВК». Локальное поле очищается
сразу после отправки; его содержимое не сохраняется. Кнопка «Открыть канал после
входа» возвращает управление странице канала. Проверка на искусственных формах
подтверждает ввод, клавиши, переход в окно авторизации и возврат в канал.

2026-10-04 пользователь явно разрешил постоянный ключ записи в репозиторий
и автоматическую публикацию. Выделенный deploy key `165339645` зарегистрирован
только для `MikVoron/yulia-voronova-site`; приватный ключ остаётся на сервере.
Автоматическая проверка до этого отклонила добавление ключа без отдельного
явного согласия. Серверный вход подтверждён реальным чтением 10 постов;
сессия сохранена на сервере, восстановление проверено запуском читателя.
Режим читателя `--preview` формирует закрытый файл ссылок; отдельный издатель
автоматически публикует его. Это рабочее разделение чтения и записи.

`scripts/run-blog-vk-server.sh` запускает читатель и издатель с отдельными
блокировками. `scripts/activate-blog-vk-server.sh` предназначен только для
исполнения после явного разрешения ключа: проверяет чистый checkout, выполняет
первую реальную публикацию и затем добавляет две записи crontab пользователя.
Проверка запуска читателя выполняется каждую минуту (работающий процесс
защищён flock), публикация — каждые пять минут. Другие задания crontab сохраняются.
Ключ принадлежит только этому репозиторию и не позволяет менять его настройки,
но технически может записывать любые файлы репозитория. Код издателя ограничивает
публикуемые изменения таблицей ссылок; это не сужает права самого deploy key.
