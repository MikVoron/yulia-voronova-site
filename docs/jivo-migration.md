# Замена Tawk на Jivo

Подготовлено 30 октября 2026 года. Виджет: `dQilQUP0Lq`.
Изменения пока относятся к рабочим файлам, а не к установленной production-версии.

## Поведение

На основном сайте кнопка «Оператор» открывает Jivo. На страницах SmartPlate
кнопки поддержки, ссылки помощи при входе и ссылки из статусов платежей
открывают Jivo в существующем окне «Чат с отделом заботы».
Загрузка поставщика начинается после нажатия. При ошибке или ожидании дольше
12 секунд доступна ссылка `hello@voronova.online`.

Общая логика основного сайта — `jivo-support.js` и `jivo-support.css`.
Все страницы, подключавшие `analytics.js`, подключают эти файлы и новые версии
основного JS/CSS. `analytics.js` сохраняет Метрику и GA; Tawk из него удалён.
Версия кэша service worker изменена, чтобы ранее сохранённые файлы обновились.

В SmartPlate используются `platform/jivo-chat-modal.js` и одноимённый CSS.
Сам виджет выполняется на `https://voronova.online/support-chat.html`;
доступ к аккаунту SmartPlate ему не нужен и не предоставляется.
Родительская CSP разрешает только этот точный origin iframe; разрешения для
внешних скриптов и соединений на страницах аккаунта не добавлены.
Старая пара `tawk-chat-modal.*` оставлена для ранее закэшированных страниц;
активные страницы её больше не подключают.

Готовность определяется успешным вызовом API Jivo после инициализации,
а не загрузкой iframe. Сообщения iframe проверяются по origin и окну-источнику.

## Проверка

`node scripts/test-jivo-browser.cjs` проверяет рабочие файлы в Chrome по
production-адресам через перехват запросов. Применяется CSP из конфигурации
nginx. Внешний виджет настоящий; запросы к production API и аналитике блокируются,
сообщения не отправляются. Это локальная проверка, а не доказательство установки.
Скриншоты и результаты находятся в `tmp/jivo-20261030/`.

Целевые проверки CSP из каталога `server`:

```powershell
node node_modules/vitest/vitest.mjs run __tests__/csp-external-scripts.test.mjs -t 'shared Jivo modal|allows approved analytics origins'
```

На актуальной релизной ветке полный CSP-набор даёт 18 успешных проверок и
четыре прежних ошибки: старые ожидания для login, главной, кабинета и версии
редактора рецептов. Повторное объявление `loginLink` было только в исходном
незавершённом рабочем дереве и в релиз не включено. Эти ошибки не исправляются
в рамках замены чата. Сравнение со снимком до изменений сохранено рядом
с результатами браузерной проверки.

## Порядок установки

1. Сначала установить на основном сайте `support-chat.html`, `jivo-support.js`
   и `jivo-support.css`; проверить реальное открытие формы, включая мобильную.
2. Установить новые файлы и ссылки основного сайта, обновлённый JS/CSS и `sw.js`.
3. В SmartPlate установить новую пару `jivo-chat-modal.*`, изменённые шесть HTML,
   `cabinet.js` и упоминание поставщика в политике данных.
4. Применить обе изменённые CSP в nginx (`plate.voronova.online`), проверить
   `nginx -t` перед reload.
5. Проверить открытие, ввод текста, закрытие и повторное открытие на реальных
   доменах с desktop/mobile. Доставку сообщения оператору считать подтверждённой
   только после отдельной отправки и проверки получения.

В рабочем дереве есть другие незавершённые изменения. При выпуске нужен
отдельный патч только этой замены; нельзя выпускать всё рабочее дерево целиком.

API и события: [официальная документация Jivo](https://www.jivo.ru/docs/widget/).

## Подготовка релиза

Патч перенесён на актуальную `origin/main` в отдельном worktree.
Пять сценариев Chrome проходят на этой версии; две целевые CSP-проверки
также проходят. `scripts/test-jivo-browser.cjs --live-main` проверяет уже
опубликованный основной сайт, `--live` — оба сайта с настоящими HTML/JS/CSS
и публичными GET-запросами API. Запросы записи к API и аналитика блокируются.
Сообщения в Jivo эти проверки не отправляют.

VPS требует интерактивный sudo. Пакет для него содержит только восемь
изменённых статических файлов, два новых файла модального окна и nginx CSP.
`scripts/install-jivo-20261030.py` проверяет закреплённый хеш манифеста,
исходные/новые хеши и публичные зависимости. При установке создаёт приватную
резервную копию, проверяет nginx перед reload и сверяет установленные и
публичные байты. Ошибка вызывает откат. API не перезапускается; PID и health
проверяются до и после. Успех обозначается `JIVO_LIVE_OK`.
