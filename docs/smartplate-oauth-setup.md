Первая авторизация без email возвращает к входу по коду; ранее привязанная учётная запись может войти без повторного предоставления email.

## One Tap и предпросмотр

По запросу владельца подготовлен One Tap с ВК, Mail и Одноклассниками (`showAlternativeLogin: true`, `oauthList: ['mail_ru', 'ok_ru']`). Код всех трёх вариантов приходит в общий серверный callback VK ID с теми же правилами привязки аккаунта.

`GET /auth/oauth/vk/config` создаёт отдельную попытку и возвращает SDK только public state/challenge. Verifier и fingerprint остаются в HttpOnly-cookie, отдельной для каждой вкладки. ## Уточнение установки 31 октября 2026: ожидание CSP

Первая установка `d88c809e` создала checkpoint и остановилась на проверке CSP после reload nginx. Установщик вернул конфигурацию; до фазы API, рабочего `.env` и клиентских файлов выполнение не дошло. Независимая проверка после отката подтвердила исходные хеши файлов и здоровый API.

Миграции и восстановление БД не выполнялись; checkpoint и копия файлов выпуска сохранены приватно.

Настоящий Chrome без подмены сети проверил страницу входа на ширине 1440 и 390 px: VK ID, Mail, ОК и Яндекс видны, переполнения и ошибок JavaScript нет. Наблюдались отдельные сбои запросов аналитики; они не затронули отрисовку входа. Повторные тесты всей неизменённой прикладной части после исправления установщика не запускались: выше сохранены результаты чистого выпуска и известные старые ошибки CSP suite.

Пользователь подтвердил настоящий вход через Яндекс. Настоящий вход через VK/Mail/ОК и сохранение подписки реального пользователя пока не подтверждены. Сохранение user ID и подписок при совпадении email подтверждено изолированными PostgreSQL-тестами, но эти тесты не заменяют живой вход. Исторические разделы «не применено» выше описывают этапы до этой установки.

## Смена аккаунта с экрана подписки

После успешного входа через Яндекс пользователь сообщил, что повторное открытие формы входа возвращает в сохранённый аккаунт. В коде подтверждён автоматический возврат авторизованного посетителя; экран подписки не предлагал сменить учётку.

Подготовлена ссылка «Войти в другой аккаунт» на экране подписки. Она ждёт завершения текущего refresh и подтверждённого удаления серверной сессии, использует общий с refresh браузерный lock и затем очищает локальную сессию и незавершённые формы входа. Сетевой/HTTP-сбой сохраняет текущую учётку и позволяет повторить выход. Повторный клик во время запроса подавляется. Подписки и профиль на сервере не меняются.

Проверки: 24 теста переключения, refresh и email-входа прошли; Chrome на 390 и 1440 px подтвердил отказ/повтор, ожидание сервера, один запрос при двойном клике, очистку старой сессии, сохранение return URL и доступность ввода другой почты без возврата в прежний аккаунт. На момент этого коммита исправление ещё не установлено.
