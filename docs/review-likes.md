# Лайки отзывов и ответов

Лайк доступен всем зарегистрированным незаблокированным пользователям, включая администраторов, независимо от подписки. Одинаковая кнопка «Нравится» работает у основного отзыва, сообщения в обсуждении и существующего ответа Юлии на страницах рецепта, категории и ингредиента. Повторное нажатие снимает лайк. Звёзды, число отзывов и загрузка фотографий не меняются.

После успешного добавления лайка сердечко коротко увеличивается и возвращается к исходному размеру за 380 мс. При снятии лайка или ошибке запроса анимация не запускается. Системная настройка `prefers-reduced-motion: reduce` отключает её. Проверено в браузере на ширинах 320 и 1366 px, включая уменьшение движения и ошибку сети.

Уведомления в личном кабинете включены по умолчанию. Письма о лайках выключены по умолчанию и включаются отдельно. Оба переключателя находятся в разделе «Настройки»; там же доступна история уведомлений с загрузкой следующих страниц. Непрочитанные лайки также показываются в существующем колокольчике вместе с новостями. Открытие уведомления отмечает только его прочитанным и ведёт к соответствующему отзыву.

Первый лайк данного пользователя на конкретное сообщение создаёт одно уведомление автору. Собственный лайк не уведомляет автора. Снятие и повторное добавление лайка, повтор запроса и параллельные одинаковые запросы не создают дополнительных уведомлений. При снятом лайке уведомление скрывается, при повторном добавлении возвращается с прежним временем и признаком прочтения. При выключенных уведомлениях новые события не сохраняются; включение настройки не создаёт уведомлений о прошлых лайках. Заблокированные получатели не получают уведомлений.

Миграция переносит старые отметки «Полезный ответ» в лайки ответов Юлии без уведомлений о переносе. Старый endpoint возвращает 410 с просьбой обновить страницу, чтобы закешированный клиент не создавал отдельное состояние реакций.

## Контракт API

- `PUT /content/review-likes/:type/:id`, тело `{ "active": true|false }`, где `type` — `review`, `comment` или `reply`. Для `reply` используется ID основного отзыва. Ответ: `likeCount`, `likedByCurrentUser`. Сервер устанавливает заданное состояние; сетевой повтор не переключает его обратно.
- Списки отзывов и сообщений содержат `likeCount` и `likedByCurrentUser`, включая вложенные сообщения и ответ Юлии. Гости видят счётчики, а нажатие предлагает вход.
- `GET/PUT /auth/review-like-settings`: `{ "enabled": boolean, "email": boolean }`. Главный переключатель отключает оба канала, сохраняя выбор почтового переключателя.
- `GET /content/review-like-notifications`: до 20 элементов, `hasMore`; `before` — ID последнего элемента предыдущей страницы; `unread=true` — только непрочитанные. Доступна только собственная история, без email других участников.
- `POST /content/review-like-notifications/:id/read` отмечает только собственное уведомление.
- `POST /content/review-like-notifications/read`, тело `{ "ids": [...] }` (до 500 ID), отмечает показанные собственные уведомления при закрытии колокольчика. Новые рецепты и лайки используют раздельные ключи прочтения, даже если их числовые ID совпадают. `unread=true&all=1` возвращает полный список непрочитанных лайков для точного счётчика; история в кабинете остаётся постраничной.

Лайк и уведомление сохраняются одной транзакцией PostgreSQL. Строки снятых лайков сохраняются для подавления повторных уведомлений. Внешние ключи удаляют лайки и уведомления вместе с удаляемым сообщением. Почта отправляется после фиксации транзакции с повторной проверкой настроек. Отправка имеет одну попытку, ошибки SMTP записываются в журнал; автоматической повторной доставки писем нет. Внутреннее уведомление при ошибке почты сохраняется.

## Установка

1. Сверить изменения с текущими файлами сервера и сохранить его независимые изменения. Эта рабочая копия основана на `origin/main` с уже установленной в этой версии системой фотографий.
2. Применить `server/migrations/044_review_likes.sql` с резервной копией БД. Миграцию можно повторять; требуются существующие таблицы отзывов, ответов, обсуждений и старых реакций.
3. Установить `server/src/review-likes.js`, обновлённые `review-discussions.js`, `routes/content.js`, `email.js` и перезапустить API.
4. Установить изменённые JS/CSS/HTML платформы и новый `platform/review-like-settings.js` вместе. Изменённые версии подключений обеспечивают загрузку новых компонентов. `data-v2.js` обновлён во всех девяти HTML, которые его подключают.
5. Проверить хеши установленных и публичных файлов, здоровье API, CORS PUT, публичное чтение и мобильный/десктопный интерфейс. Отдельно проверить настоящую доставку письма на разрешённом аккаунте. Локальные проверки её не доказывают.

При откате восстанавливать API и frontend вместе, сохраняя добавленные таблицы для данных пользователей. После начала использования лайков старая система полезных ответов уже не отражает новые реакции; возвращать её как рабочий механизм без отдельного переноса данных нельзя.


Браузерные сценарии используют настоящие страницы с тестовыми ответами API при ширине 320/390/1366 px. Нативный PostgreSQL запускается во временном каталоге на loopback-порту 59480 со случайным паролем, не читает production `.env`, использует тестовые аккаунты и заглушку почты; после проверки останавливается и удаляется. Дополнительные зависимости не добавлялись.

Проверено локально 2026-11-08: 71 регрессионный тест, 8 сценариев на временном нативном PostgreSQL, 13 браузерных сценариев лайков и настроек и 7 прежних сценариев отправки, редактирования, удаления и пагинации обсуждений. В браузерных сценариях нет ошибок JavaScript и горизонтального переполнения. Снимки и JSON-отчёты лайков находятся в `tmp/review-likes/` внутри рабочей копии.

Изменения подготовлены локально. Эта инструкция сама по себе не подтверждает установку на действующий сайт.

## Подготовка релиза, 2026-11-08

Релиз объединён с `abb7d669` (точный счётчик и прочтение новостей). Снятый через SSH снимок production дополнительно выявил уже опубликованные значки друзей платформы в API/категории и разметку гостевого блока главной. Они сохранены в затрагиваемых файлах. Живые `style-v4.css`, глобальные зависимости и код фотографий не заменяются; их контрольные суммы входят в проверки неизменности.

`scripts/build-review-likes-release.py` собирает только закоммиченные Git-блобы 20 файлов против проверенного снимка `.local/production-before`. `scripts/install-review-likes-20261108.py check --manifest-sha <SHA>` проверяет пакет, старые/новые хеши и 10 неизменяемых файлов, JS-синтаксис, здоровье и UID/GID API. `apply` требует интерактивного sudo, делает защищённый checkpoint и свежий полный дамп БД, проверяет миграцию с ROLLBACK, устанавливает API раньше frontend, выполняет проверки публичных ассетов и автоматически возвращает затронутые файлы при ошибке. Миграция при откате сохраняется. `.env`, nginx и фотофайлы не меняются. При смешанном или неизвестном состоянии production установщик отказывается от записи.

После объединения проверены 91 регрессионный тест, 8 нативных PostgreSQL-сценариев и 13 браузерных сценариев. 10 тестов установщика на временных файлах проверяют хеши, scope, сохранность зависимостей, порядок установки и откат. Это подготовка релиза; факт живой установки должен подтверждаться отдельно после запуска `apply` оператором.
