# SmartPlate: post-MVP roadmap

Этот список не должен блокировать первый запуск. Сюда вынесены задачи, которые стоит делать после MVP, когда появятся первые пользователи, обратная связь и реальные данные по поведению.

## 1. Оплата и подписка

- Подключить автоматическую оплату вместо ручного подтверждения платежей.
- Добавить webhooks платежного провайдера и идемпотентную обработку платежей.
- Сделать автоматические email/Telegram-уведомления: оплата принята, доступ активирован, подписка скоро закончится.
- Добавить нормальные тарифы, промокоды и историю продлений.
- Добавить отдельную страницу управления подпиской: продлить, отменить, скачать чек/подтверждение.

## 2. Персонализация

- Сохранённые предпочтения пользователя: без глютена, растительное, без рыбы, без сои, любимые категории.
- Персональная главная: недавно смотрели, избранное, продолжить собирать тарелку.
- Рекомендации рецептов на основе фильтров, избранного и добавлений в тарелку.
- Персональные подсказки: "вам подходят эти рецепты", "добавьте белок", "не хватает клетчатки".
- Настройки порций и целей: похудение, поддержание, набор, семейные порции.

## 3. Планирование питания

- План питания на день и неделю.
- Список покупок по выбранным рецептам.
- Масштабирование порций и пересчёт ингредиентов.
- Быстрая замена ингредиента или блюда в плане.
- Экспорт списка покупок в заметки, PDF или мессенджер.

## 4. Умный поиск и каталог

- Серверный поиск вместо полностью клиентской фильтрации, если рецептов станет много.
- Отдельный list/detail API: в списке отдавать только лёгкие поля, полный рецепт грузить отдельно.
- Синонимы и опечатки в поиске: "паста", "макароны", "спагетти".
- Сортировки: популярное, новое, быстрое, низкая калорийность, больше белка.
- Сохранённые подборки: быстрые ужины, растительные завтраки, обеды на работу.

## 5. Аналитика продукта

- Логировать ключевые события: `recipe_view`, `paywall_seen`, `login_success`, `payment_submit`, `favorite_add`, `plate_add`, `search_used`.
- Собрать простую воронку: главная -> рецепт -> paywall -> login -> payment -> activation.
- Отслеживать конверсию trial -> active.
- Считать удержание: возвращения на 1, 7 и 30 день.
- Добавить админский дашборд по продуктовым метрикам.

## 6. Наблюдаемость и поддержка

- Подключить Sentry или аналог для frontend/backend ошибок.
- Добавить Telegram/email-алерты на 500-ошибки, падение API, проблемы cron и backup.
- Сделать correlation/request id в логах.
- Добавить страницу статуса или хотя бы внутренний health dashboard.
- Добавить удобный support-flow: пользователь пишет проблему, админ видит контекст аккаунта и последние события.

## 7. Безопасность

- Включить `Content-Security-Policy-Report-Only`, собрать нарушения, затем постепенно ужесточить CSP.
- Уменьшить количество inline JS и inline event handlers.
- Добавить регулярный XSS-регрессионный тест для отзывов, feedback и payment comments.
- Добавить audit trail для действий админа: подтверждение оплаты, блокировка, продление, редактирование рецепта.
- Проверить хранение скриншотов платежей и аватаров: сроки хранения, размер, доступ, удаление.

## 8. Производительность

- Убрать лишние payload-поля из списков рецептов после появления server-side detail API.
- Добавить HTTP-cache для статических ассетов с версионированием.
- Перенести тяжёлые изображения/пользовательские файлы в object storage или CDN, если VPS станет узким местом.
- Добавить lazy loading для изображений и видео.
- Проверить Core Web Vitals на мобильном интернете.

## 9. Контент и админка

- Добавить чеклист готовности рецепта перед публикацией.
- Добавить preview режима "как видит пользователь без подписки" и "как видит подписчик".
- Добавить bulk-операции для категорий, тегов и публикации.
- Сделать журнал изменений рецепта.
- Добавить валидацию контента: нет фото, нет шагов, нет КБЖУ, конфликт категорий, пустые добавки.

## 10. Дизайн и UX

- Провести полноценный mobile-first UX review после первых пользователей.
- Улучшить onboarding: объяснить "тарелку", баланс блюда, избранное и подписку.
- Сделать более сильный paywall с демонстрацией ценности.
- Добавить красивые skeleton loaders и состояния ошибок на все ключевые экраны.
- Собрать небольшой дизайн-системный слой: кнопки, карточки, empty/error states, модалки, form controls.

## 11. Юридическое и доверие

- Юридически вычитать оферту, политику обработки персональных данных и условия подписки.
- Добавить понятную страницу "как работает подписка".
- Добавить правила возвратов и поддержки.
- Добавить публичные контакты для вопросов по оплате.
- Проверить соответствие хранения персональных данных фактической инфраструктуре.

## 12. Возможные большие фичи

- AI-помощник по замене ингредиентов и сборке тарелки.
- Генерация меню на неделю под ограничения пользователя.
- Интеграция с Telegram-ботом.
- Экспорт рецептов/планов в PDF.
- Семейные аккаунты или общий список покупок.
- Нативное мобильное приложение, только если web-продукт подтвердит спрос.

## Приоритет После MVP

1. Автоматизация оплаты и поддержка платежных проблем.
2. Аналитика продуктовой воронки.
3. Sentry/алерты и улучшенная наблюдаемость.
4. План питания и список покупок.
5. Персонализация и рекомендации.
6. CSP и снижение XSS-поверхности.
7. Серверный поиск и list/detail API при росте каталога.
